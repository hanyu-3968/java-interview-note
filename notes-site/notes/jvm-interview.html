G1/ZGC 原理 + 对象晋升 + OOM 定位 + MAT 四步 + 收集器选型。

一、G1 收集器工作原理

Region 分块，垃圾优先，时间一到，立马停手。

核心设计说明面试关键词
Region 划分 堆分为约 2048 个等大小 Region（1~32MB），不再有连续年轻代/老年代 Region、分区
可预测停顿 每次只选垃圾最多的 Region 清理（Garbage-First），时间到了就停 Garbage-First、MaxGCPauseMillis
停顿模型 用户设定 -XX:MaxGCPauseMillis（默认 200ms），JVM 动态调整 软实时、目标暂停

补充：G1 不是"更好的 CMS"。CMS 是连续老年代 + 标记清除（有碎片），G1 是 Region 分区 + 标记整理（无碎片），架构完全不同。G1 通过"只扫最脏的 Region"实现可预测停顿，不是"扫得更快"。

二、ZGC 超低延迟原理

染色指针贴标签，读屏障自动导航，用户不停顿。

核心设计说明面试关键词
染色指针 对象引用中编码额外状态信息（标记、重定位等） 染色指针、Colored Pointers
读屏障 用户线程读对象时，如果对象被移动了，自动重定向到新地址 Load Barrier、并发移动
并发整理 标记、移动、重定位全部与用户线程并发执行 STW < 1ms、亚毫秒级

补充：ZGC 的"亚毫秒级停顿"靠的是染色指针 + 读屏障实现并发移动对象，不是"GC 跑得更快"。读屏障在用户线程读对象时自动修正指针，所以用户线程几乎不感知移动。代价是读屏障有微小开销，适合超大堆（>64GB）场景。

三、对象晋升机制

年龄到、对象大、放不下、同龄过半。

晋升方式触发条件关键参数
年龄阈值熬过 15 次 Minor GC-XX:MaxTenuringThreshold=15
大对象直接分配对象大小超过阈值-XX:PretenureSizeThreshold（仅 Serial/ParNew）；G1 中为 G1HeapRegionSize 的一半
Survivor 空间不足Minor GC 后存活对象放不下 Survivor空间分配担保失败 → Promotion failed
动态年龄判定Survivor 中同龄对象总大小 ≥ Survivor 区一半此年龄及以上对象全部晋升

补充：动态年龄判定不是"年龄到 15 才晋升"。Survivor 中相同年龄对象总和大于一半 Survivor 空间，大于等于该年龄的对象直接晋升——所以可能 3 岁就全部晋升了，不用等到 15。

四、JIT 编译与逃逸分析

HotSpot 靠标量替换实现"栈上分配"效果。

概念说明面试关键词
JIT 编译器热点代码编译为本地机器码并缓存C1（快速编译）、C2（激进优化）、分层编译
逃逸分析分析对象是否逃逸出方法或线程不逃逸、方法逃逸、线程逃逸
栈上分配（效果）不逃逸对象直接在栈上分配，方法结束即销毁减轻 GC 压力
标量替换（核心）将对象字段拆解为独立标量，在栈/寄存器中直接使用-XX:+DoEscapeAnalysis（JDK8 默认开启）

补充（面试陷阱）：HotSpot 没有独立实现栈上分配，而是通过标量替换达到类似效果！说"栈上分配"时要补一句"实际是标量替换实现的"，否则面试官会追问。

六、MAT 定位内存泄漏 · 4 步走

Leak Suspects → Dominator Tree → Path to GC Roots → OQL。

  1. Leak Suspects Report：看自动报告，找可疑大对象。
  2. Dominator Tree：按 Retained Heap 排序，找最大对象。
  3. Histogram + Path to GC Roots：排除弱/软引用，追到持有强引用的代码。
  4. OQL 精确查询：SELECT * FROM byte[] WHERE length > 1MB。

常见泄漏场景：HashMap/ArrayList 无界缓存、ThreadLocal 未 remove、监听器未注销。

补充：Path to GC Roots 必须排除弱/软/虚引用，只看强引用链。弱/软/虚引用会被 GC 正常回收，不是泄漏根因；只有强引用链持有才是真正的泄漏。

九、面试串联话术

原理→排查→选型一气呵成。

线上 CPU 飙高，我会先 top 找进程，再 top -Hp 找线程，转十六进制后用 jstack 定位代码行。如果是 GC 线程在忙，用 jstat 看 GC 频率，再用 jmap 导 Dump 用 MAT 分析——Leak Suspects 看全局，Dominator Tree 找大对象，Path to GC Roots 追到泄漏代码。

调优时，我会先明确目标（延迟<200ms），再开启 GC 日志采集数据。如果 Full GC 频繁但老年代不降，大概率是内存泄漏，重点排查集合缓存和 ThreadLocal 未清理。参数上，-Xms 和 -Xmx 设为相同避免动态扩容，-XX:+DisableExplicitGC 屏蔽人为触发。

收集器选型方面，离线批处理用 Parallel GC 保吞吐量，高并发交易用 G1 控暂停，金融敏感接口用 ZGC 追求亚毫秒级。每次调优必须在预发环境压测验证，达标才能上线——这是工程化闭环。
