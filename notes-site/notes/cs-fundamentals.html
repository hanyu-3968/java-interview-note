进程线程加锁，数据结构选型，JVM 网络 文件系统。

一、计算机原理：进程、线程与锁

程序加载成进程，线程并发共享数据要加锁。

概念定义关键点记忆画面
程序 静态的代码文件 躺在硬盘上没执行 菜谱写在纸上
进程 程序加载进内存后的运行实例 有独立内存空间 菜谱下锅开炒了
线程 进程内轻量级执行单元 共享进程内存，切换成本低 一个厨房多个厨师
临界区 多线程并发修改共享数据的代码段 并发访问会出问题 多人抢同一口锅
锁 通过 CAS/信号量保证临界区互斥 解决竞争但会阻塞 锅前挂"占用中"牌
线程安全 多线程并发执行结果与单线程一致 靠隔离或加锁实现 各炒各的不互相干扰

锁的代价与缓解

锁能解决线程安全问题，但锁竞争会引起线程阻塞，导致系统响应变慢。最终需通过分布式架构、限流、降级等手段缓解。

层次手段解决的问题记忆画面
单机 CAS + 信号量 临界区互斥 门上挂锁
单机 线程栈隔离 方法内基本类型天然安全 各厨师自带调料盒
分布式 分布式锁 跨进程互斥 多厨房共用一把锁
架构 限流 + 降级 锁竞争过载、响应变慢 高峰期分流+关非核心

补充："线程安全"不是"加了锁才安全"。方法内定义的基本类型变量会被每个线程放入自己的 Java 栈中，栈彼此隔离，这些变量天然线程安全，不需要加锁。需要加锁的是多个线程共享的数据（如堆里的对象实例、静态变量）。

二、数据结构：线性表、Hash 表与树

一对一选线性表，哈希映射选 Hash，一对多选树。

2.1 线性表：一对一的存储基础

每个元素只有一个前驱和一个后继。数组和链表是存储基础，栈和队列是操作受限的线性表。

结构存储方式访问查找插入/删除记忆画面
数组 内存中一块连续空间 随机访问 O(1) 按值遍历 O(n) 需移动元素 O(n) 一排连座电影院，对号入座
链表 零散内存，节点含数据+指针 只能顺序遍历 O(n) O(n) 改指针 O(1) 寻宝游戏，每张纸条指向下一张
栈 操作受限线性表，LIFO 栈顶 O(1) — 入栈/出栈 O(1) 弹夹后进先出，栈顶是当前方法
队列 操作受限线性表，FIFO 队头 O(1) — 入队/出队 O(1) 排队取号，先到先得

补充："数组访问 O(1)"指的是按下标随机访问（连续内存直接算地址），"按值查找"仍要遍历是 O(n)。链表"插入删除 O(1)"前提是已经定位到目标节点，定位本身是 O(n)，不能笼统说"链表插入比数组快"。

2.2 Hash 表：哈希函数把查找压到 O(1)

特殊结构，存取原理：计算 key 的哈希值（hashCode）→ 计算数组下标 → 直接访问该位置。

维度说明记忆画面
存取原理 key → hashCode → 数组下标 → 直接访问 寄存柜按号码牌直接开柜
理想复杂度 无冲突时 O(1) 一柜一物，秒取
哈希冲突 不同 key 算出相同下标 两个号码牌指向同一柜
链表法 冲突位置挂链表存多个元素 柜里挂一串小袋子
Java 8 优化 链表过长转红黑树，优化到 O(log n) 串太长改用抽屉分层
最坏情况 所有 key 冲突，退化成链表 O(n) 全挤一个柜，挨个翻

补充：为什么是 O(1)？查找过程是"计算下标 → 直接访问"，没有遍历，时间恒定。严格说是平均 O(1)、最坏 O(n)（所有 key 冲突退化成链表）。"Hash 表查找 O(1)"是平均情况，一旦哈希函数设计差或 key 分布极端，退化成链表遍历就是 O(n)。Java 8 加红黑树正是为了把最坏从 O(n) 拉回 O(log n)。

2.3 树：打破一对一的层次结构

非线性表，每个元素可以有多个后继，用于表达层次关系和高效查找。

对比项线性表树记忆画面
元素关系 一个前驱一个后继 一个前驱多个后继 线性表单行道，树分叉路
典型结构 数组/链表/栈/队列 二叉树/BST/红黑树 线性表一串，树一层层展开
用途 顺序存储、简单操作 层次结构、高效查找 线性表排队，树查家谱
查找复杂度 数组 O(n)、Hash O(1) BST O(log n) 线性表挨个找，树折半砍

补充："树查找 O(log n)"指的是二叉搜索树（BST）平衡时的情况。普通二叉树最坏退化成链表仍是 O(n)；红黑树/AVL 树通过自平衡保证 O(log n)。Hash 表 O(1) 比树 O(log n) 更快，但 Hash 表无序不能范围查询，树（如 BST/B+ 树）支持范围查找，这是数据库索引用 B+ 树而非 Hash 的原因。

三、JVM 原理：从 java 命令到字节码执行

类加载→方法区→栈帧→堆→执行引擎翻译执行。

JVM 启动执行流程

步骤动作关键组件记忆画面
1 java xxx 启动 类加载器 按开关通电
2 加载 class 存入方法区 方法区 把菜谱贴到厨房公告栏
3 创建主线程，分配 PC + Java 栈 程序计数器、Java 栈 主厨上岗，备好工作台
4 执行 main，在栈中创建栈帧 栈帧 开一道菜，铺一张案板
5 遇 new 在堆中分配内存 堆 取食材放案板旁
6 对象地址记录在栈帧 栈帧引用 案板上记食材存放位置
7 执行引擎读字节码翻译 CPU 执行 执行引擎 厨师按菜谱一步步炒
8 调用其他方法压入新栈帧 栈顶切换 新菜叠在旧菜上，先做新菜
9 方法返回栈帧出栈恢复调用者 栈帧出栈 菜做完撤案板，回上一道

从 Java 栈看线程安全

情形是否线程安全原因记忆画面
方法内基本类型变量 安全 每个线程放入自己的栈，栈彼此隔离 各厨师自带调料盒
方法内创建对象，引用未离开方法 安全 对象虽在堆，但其他线程访问不到 食材放案板旁，别人够不着
方法内对象被返回或放入外部容器 不安全 引用逃逸出方法，多线程可访问 食材端上公共餐桌，多人抢

补充："对象在堆中"不等于"对象不安全"。关键看引用是否逃逸出方法：如果对象只在方法内使用、没被返回也没放进外部容器，虽然物理上在堆里，但其他线程拿不到引用，仍是线程安全的。一旦引用逃逸（返回、存入静态字段、传入其他线程），就要考虑同步。

DNS 找 IP，CDN 就近缓存，TCP 握手，LB 分发。

网络分层与核心组件

组件所在层职责记忆画面
HTTP 应用层 约定数据编码协议 双方约定用什么语言写信
TCP 传输层 建稳定连接，bit 流可靠传输 邮政专线，件件送达

TCP 三次握手

APP 和服务器之间发三次报文才建立一个 TCP 连接。

步骤方向标志含义
第一次 客户端 → 服务器 SYN 请求建立连接
第二次 服务器 → 客户端 SYN+ACK 确认并请求建立连接
第三次 客户端 → 服务器 ACK 确认，连接建立

CDN 与 LB 实战（淘宝场景）

为提高访问速度、降低数据中心负载，淘宝在全国各主要运营商接入机房部署缓存服务器，缓存静态图片资源等，构成 CDN。HTTP 请求到达数据中心时，先到负载均衡服务器（DNS 解析出的就是 LB 的 IP），再由 LB 分发到搜索服务器集群的某台机器。

补充：DNS 解析出的 IP 不一定是业务服务器，在大型架构里往往是负载均衡服务器的 IP。LB 再按策略（轮询/最少连接/哈希）把请求分发到后端集群。CDN 缓存的是静态资源（图片、JS、CSS），动态接口仍要回源到数据中心，不能笼统说"CDN 让所有请求都变快"。

六、高频场景题

Hash O(1) 最坏 O(n)，栈隔离安全，DNS 解析 LB。

"Hash 表为什么查找是 O(1)？最坏呢？"

查找过程是"计算 key 的 hashCode → 算出数组下标 → 直接访问"，没有遍历，时间恒定，所以平均 O(1)。最坏情况是所有 key 冲突退化成链表，变成 O(n)；Java 8 链表过长转红黑树，把最坏拉回 O(log n)。

"数组访问 O(1) 和 Hash 查找 O(1) 一样吗？"

不一样。数组 O(1) 是按下标随机访问（连续内存直接算地址）；Hash O(1) 是按 key 经哈希函数算下标再访问。数组按值查找仍是 O(n)，Hash 按 key 查找才是 O(1)。

"从 Java 栈角度怎么理解线程安全？"

方法内定义的基本类型变量会被每个线程放入自己的 Java 栈，栈彼此隔离，所以这些变量天然线程安全。方法内创建的对象，只要引用没逃逸出方法（没返回、没放入外部容器），虽在堆中但其他线程访问不到，也安全；一旦引用逃逸就要考虑同步。

"DNS 解析出的 IP 一定是业务服务器吗？"

不一定。大型架构里 DNS 解析出的常是负载均衡服务器的 IP，LB 再把请求分发到后端集群某台机器。CDN 场景下解析出的还可能是 CDN 边缘节点的 IP，就近返回缓存静态资源。

"Inode 满了和硬盘满了有什么区别？"

硬盘满是数据块用尽，df 显示空间不足；Inode 满是文件控制块耗尽，df 显示有空间但无法新建文件（"No space left on device"）。Inode 数量在文件系统创建时定死，大量小文件易耗尽 Inode。

七、面试回答模板

三句话讲清计算机基础五层选型与实战。

问题本质是问计算机基础的某一层——进程线程与并发、数据结构选型、JVM 运行流程、网络编程链路、还是文件系统存储，先定位"问的是哪一层"再展开。

机制是程序加载进内存成进程、进程内分线程，并发改共享数据靠锁（CAS/信号量）但竞争会阻塞需限流降级；数据结构按一对一/哈希/一对多选线性表/Hash/树，Hash 平均 O(1) 最坏 O(n)，BST 平衡 O(log n)；JVM 走类加载→方法区→栈帧→堆→执行引擎的链路，栈内变量天然隔离；网络靠 DNS 找 IP、CDN 就近缓存、TCP 三次握手建连、LB 分发到集群；文件系统用 Inode 记元信息+索引数据块地址。

实战中我会根据场景选型：高并发共享数据用锁+限流降级，查找密集用 Hash 表，范围查询用树，静态资源上 CDN，请求经 LB 分发，日志放机械盘、系统放固态盘，并关注 Inode 别被小文件耗尽。

八、最后复习：闭眼回忆 8 句

八句话串起计算机基础五大块。

  1. 程序是静态代码，加载进内存成进程，进程内轻量执行单元叫线程。
  2. 多线程并发修改共享数据（临界区）会出线程安全问题，靠 CAS/信号量加锁解决，但锁竞争会阻塞，最终靠限流降级缓解。
  3. 线性表一对一：数组连座随机访问 O(1) 按值查找 O(n)，链表零散插删 O(1) 查找 O(n)，栈 LIFO 服务方法调用，队列 FIFO 服务排队。
  4. Hash 表靠哈希函数算下标直接访问，平均 O(1) 最坏 O(n)，链表法解冲突，Java 8 长链转红黑树 O(log n)。
  5. 树打破一对一，一对多表达层次，BST 平衡 O(log n)，Hash 无序不能范围查询所以数据库索引用 B+ 树。
  6. JVM 流程：类加载→方法区→主线程（PC+Java 栈）→main 栈帧→new 进堆→执行引擎翻译字节码→方法调用压新栈帧→返回出栈。
  7. 网络链路：DNS 翻译域名、CDN 就近缓存静态资源、TCP 三次握手（SYN/SYN+ACK/ACK）建连、LB 把请求分发到集群某台机器。
  8. 文件系统：机械盘存日志、固态盘存系统和随机读写，硬盘按块划分，Inode 记元信息+索引数据块地址，Inode 满了有空间也建不了文件。
