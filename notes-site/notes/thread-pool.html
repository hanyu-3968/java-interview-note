7 大参数 + 先队列后扩线程 + 4 种拒绝策略 + 阻塞队列设计哲学。

一、什么是线程池

复用线程 + 控制并发，生产必须手动创建杜绝无界队列。

价值说明
复用线程避免频繁创建销毁的开销
控制并发控制线程数量和队列，避免资源耗尽
任务流转核心线程优先 → 任务队列次之 → 最后才扩张到最大线程数
生产准则务必手动创建，杜绝无界队列

补充：线程池不是"线程越多越好"。线程是昂贵的操作系统资源（1MB 栈内存 + 内核调用），无限制创建会拖垮系统。线程池的核心是用"常驻核心线程 + 队列缓冲 + 临时非核心线程"三层结构，在吞吐和稳定之间找平衡。

二、创建线程的四种方式

生产环境只用线程池。

方式特点
继承 Thread 类单继承限制，扩展性差
实现 Runnable 接口无返回值
实现 Callable 接口 + Future支持返回值
使用线程池最推荐，生产环境标准

速记：Thread、Runnable、Callable+Future、线程池。生产环境只用线程池。

三、线程池的 7 大参数

核心线程、队列、最大线程、存活时间、单位、线程工厂、拒绝策略。

参数作用关键点
核心线程数（corePoolSize）常驻线程即使空闲也保留
阻塞队列（workQueue）缓冲任务必须用有界队列，无界队列会让最大线程数失效
最大线程数（maximumPoolSize）极限并发队列满后才创建非核心线程
存活时间（keepAliveTime）非核心线程空闲存活时间超时回收
时间单位（unit）存活时间单位-
线程工厂（threadFactory）创建线程可自定义命名便于排障
拒绝策略（RejectedExecutionHandler）满了怎么办4 种内置策略

补充："先放队列，队列满了才扩线程"是反直觉但正确的设计。如果用了无界队列，队列永远不满，最大线程数就永远失效——这就是为什么金融项目强制用有界队列 + 自定义拒绝策略 + 队列水位监控（超 80% 立马报警扩容）。

四、阻塞队列的作用与设计哲学

缓冲 + 解耦，线程昂贵队列廉价所以先队列后扩线程。

作用说明
缓冲任务提交速度大于处理速度时，队列暂存，防止系统被瞬间流量冲垮
解耦提交任务的线程和执行任务的线程通过队列隔离

为什么先放队列再扩线程？

理由说明
最大化资源利用率排队是廉价的 JVM 内存操作，创建线程是昂贵的操作系统操作
规避无限创建避免流量一来就无限创建线程导致系统崩溃
应对瞬时毛刺80% 的高峰是短时毛刺，排队让核心线程消化即可，不必动用非核心线程

设计比喻：corePoolSize 是常驻兵力，workQueue 是防御缓冲带，maximumPoolSize 是最后的核武器（Emergency Only）。只有缓冲带被洪水冲垮时，才动用核武器。一上来就用核武器，系统很快因资源耗尽而自爆。

补充："队列满了才扩线程"不是"队列满了就拒绝"。顺序是：核心线程 → 队列 → 最大线程 → 拒绝策略。队列满后还会尝试创建非核心线程到 maximumPoolSize，只有最大线程也满了才拒绝。

五、四种拒绝策略

Abort 抛异常、CallerRuns 反压、Discard 丢弃、DiscardOldest 丢最旧。

策略行为风险/适用
AbortPolicy（默认）直接抛出异常暴露问题，但会中断提交线程
CallerRunsPolicy调用者线程执行任务降速反压，不丢任务
DiscardPolicy丢弃任务风险高，静默丢失
DiscardOldestPolicy丢弃队列中最旧的任务给新任务腾位，可能丢重要任务

补充：CallerRunsPolicy 看似"退化了"，其实是反压的好策略——让提交任务的线程自己去执行，自然就慢下来不再疯狂提交，起到限流作用。生产环境常用它配合有界队列，既不丢任务又能反压。

六、面试串联话术

参数→队列→拒绝策略一气呵成。

线程池复用线程避免创建销毁开销，控制并发避免资源耗尽，生产必须手动创建杜绝无界队列。7 大参数：核心线程、阻塞队列、最大线程、存活时间、时间单位、线程工厂、拒绝策略。

任务流转：核心线程优先 → 队列次之 → 最大线程兜底 → 拒绝策略。先队列后扩线程是因为线程昂贵（1MB 栈+内核调用）队列廉价（JVM 内存），应对毛刺。无界队列会让最大线程数失效，流量洪峰 OOM。

四种拒绝策略：AbortPolicy 抛异常（默认）、CallerRunsPolicy 调用者执行（反压降速）、DiscardPolicy 丢弃（风险高）、DiscardOldestPolicy 丢最旧。生产用有界队列 + CallerRunsPolicy + 队列水位 80% 告警扩容。
