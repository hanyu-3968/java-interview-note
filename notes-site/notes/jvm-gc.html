可达性分析判存活，分代收集选算法，G1/ZGC 控停顿。

一、为什么要做垃圾回收

分配新对象 + 回收无引用对象，防内存耗尽。

分配新对象内存 + 回收不再被引用的对象内存，确保程序不会因内存耗尽而崩溃，同时保证被引用对象不被错误回收。

二、如何判断对象需要回收

引用计数已废弃，JVM 唯一用可达性分析。

算法原理优点致命缺陷是否主流
引用计数法 每个对象维护计数器，被引用 +1，失效 -1，为 0 则回收 实现简单、实时回收 ❌ 无法解决循环引用（A 引 B、B 引 A，永不为 0） 已废弃
可达性分析算法 从 GC Roots 出发，能到达的对象存活，否则回收 ✅ 解决循环引用 需要 STW 标记 JVM 唯一使用

GC Roots 包括：

  • 虚拟机栈（栈帧中本地变量表）引用的对象
  • 方法区中静态属性引用的对象
  • 方法区中常量引用的对象
  • 本地方法栈中 JNI 引用的对象
  • 活跃线程（Thread）

补充：GC Roots 还可包含同步锁（synchronized）持有的对象，以及 JVM 内部引用（如基本类型对应的 Class 对象、常驻异常对象、类加载器等）。

三、四种垃圾回收算法

新生代复制快，老年代标记整理稳。

算法核心逻辑优点缺点适用场景
标记-清除 标记存活对象 → 清除未标记对象 简单 ❌ 内存碎片、效率不稳定 老年代（配合 CMS）
复制算法 内存分两块，每次用一块，用完把存活对象复制到另一块，整块清理 ✅ 无碎片、效率高 ❌ 内存利用率只有 50% 新生代（主流）
标记-整理 标记存活 → 存活对象向一端移动 → 清理边界外内存 ✅ 无碎片 ❌ 移动对象开销大 老年代
分代收集 不同区域用不同算法（新生代复制 + 老年代标记整理/清除） ✅ 扬长避短 实现复杂 所有主流 JVM

记忆口诀：新生代复制快，老年代标记整理稳，CMS 标记清除有碎片。

四、分代回收完整流程

Eden→Survivor 轮换，年龄到阈值晋升老年代。

  1. 新对象 → Eden 区。
  2. Eden 满 → Minor GC：回收不活跃对象，存活对象 → Survivor0（S0）。
  3. Eden 再满 → Minor GC：Eden 存活 → S1，S0 存活 → S1（S1 放不下则提前晋升 Old）。
  4. 重复上述过程，S0/S1 轮流担当"留宿区"；每熬过一次 GC 年龄 +1，达阈值（默认 15）晋升 Old。
  5. Old 区达一定比例 → Major GC（只回收 Old，通常 CMS/G1 并发）。
  6. Old 区满 → Full GC（回收全堆，STW 最严重）。
  7. Full GC 后内存仍不够 → OutOfMemoryError（OOM）。

易混概念：

  • Minor GC = 新生代回收（频繁，速度快）
  • Major GC = 老年代回收（较慢，CMS/G1 并发）
  • Full GC = 整个堆回收（最慢，STW 最长）

补充：新生代 Eden:Survivor0:Survivor1 默认比例 8:1:1，由 -XX:SurvivorRatio 控制；对象晋升年龄由 -XX:MaxTenuringThreshold 控制（默认 15，CMS 为 6）。

五、垃圾收集器分类速查

吞吐量选 Parallel，低延迟选 G1/ZGC。

收集器线程模式核心特点暂停时间适用场景
Serial 单线程 简单高效，Client 模式默认 STW 较长 单核 CPU、内存小
Parallel（PS+PO） 多线程 吞吐量优先，Server 模式默认（JDK8） STW 较长 离线批处理、后台任务
CMS 多线程并发 标记-清除，低延迟，有碎片问题 STW 较短 中等堆内存、对延迟敏感
G1 多线程并发 Region 分区，可预测停顿时间（默认 200ms） STW 可控（50~200ms） 高并发在线交易（4~64GB 堆）
ZGC 多线程并发 染色指针 + 读屏障，超低延迟（<1ms） STW 亚毫秒级 金融交易、超大堆（>64GB）

记忆口诀：吞吐量优先 → Parallel；低延迟优先 → CMS → G1 → ZGC（越来越低）；JDK8 默认 Parallel，JDK9+ 默认 G1。

六、关键概念补充

STW 是延迟根源，空间分配担保防晋升失败。

概念说明
STW（Stop The World）GC 时暂停所有用户线程，是延迟的根源
吞吐量业务代码运行时间 /（业务代码运行时间 + GC 时间）
内存泄漏对象不再被程序使用，但 GC Roots 仍持有引用 → 无法回收 → OOM
空间分配担保Minor GC 前检查老年代剩余空间是否够容纳晋升对象，不够则提前触发 Full GC

七、面试串联话术

判活→算法→分代→收集器→调优一气呵成。

判断对象是否存活，JVM 用可达性分析，从 GC Roots 出发能到达的就是存活，否则回收。GC Roots 主要包括栈帧中的局部变量、静态变量和活跃线程。

回收算法有四种：复制算法用于新生代，效率高但耗内存；标记-清除用于老年代，但会产生碎片；标记-整理解决了碎片问题，但移动对象有开销。所以 JVM 采用分代收集，新生代用复制，老年代用标记-整理或标记-清除。

收集器选型上，Parallel 适合离线批处理，追求吞吐量；G1 适合高并发在线系统，能控制暂停在 200ms 内；ZGC 适合金融支付场景，追求亚毫秒级暂停，通过染色指针和读屏障实现并发移动对象。

调优时重点关注 FGC 次数和 STW 时长，用 jstat 看 GC 频率，用 jmap 导出 Dump 分析内存泄漏，根据业务场景选择合适的收集器和堆大小参数。
