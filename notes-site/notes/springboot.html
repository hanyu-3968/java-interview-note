run 七步启动 + 自动装配六步 + 五大特性

一、启动流程：SpringApplication.run 七步

推类型→加监听→备环境→建上下文→刷新→起容器→跑 Runner

SpringApplication.run() 是 SpringBoot 总入口，从推断应用类型到 Runner 回调，每步职责明确。

步骤动作关键产物记忆画面
1推断应用类型WebApplicationType看门口：Web 还是普通房
2加载 spring.factories监听器、初始化器招工：请好监工和师傅
3解析 application.ymlEnvironment备料：配置摆上工作台
4createApplicationContext上下文对象搭台：建好 IoC 骨架
5refresh 刷新容器Bean 定义、BeanPostProcessor开工：定义→实例化→后置
6启动内嵌 TomcatServlet 容器通水：房子接上水电
7ApplicationRunner 回调业务启动逻辑验收：交付后做收尾活

补充：监听器（ApplicationListener）监听事件，初始化器（ApplicationContextInitializer）在 refresh 前对上下文做预处理，两者不混。

二、容器刷新核心：refresh 六阶段

后置定义→注册后置→消息源→事件广播→实例化单例→发布就绪

refresh 是 Spring 老方法，SpringBoot 复用它完成 Bean 加载与实例化。

阶段方法作用记忆画面
1invokeBeanFactoryPostProcessors加载 @Bean 定义画图纸：登记零件清单
2registerBeanPostProcessor注册后置处理器请质检员：逐个检查
3initMessageSource国际化消息源备翻译：多语言文案
4initApplicationEventMulticaster事件广播器装大喇叭：事件分发
5finishBeanFactoryInitialization实例化非懒加载单例造零件：真正 new 对象
6finishRefresh发布 ContextRefreshedEvent敲锣：宣布容器就绪

补充：BeanFactoryPostProcessor 改 Bean 定义（refresh 早期），BeanPostProcessor 改 Bean 实例（实例化前后），一个改图纸一个改成品。

三、自动装配原理：@EnableAutoConfiguration 六步

开启→导入→加载候选→条件过滤→注入→用户优先

自动装配是 SpringBoot 灵魂，本质是"开启 + 加载候选 + 条件过滤 = 灵活可覆盖"。

步骤机制作用记忆画面
①@EnableAutoConfiguration开启自动配置开关按总闸：通电
②@Import(AutoConfigurationImportSelector.class)导入核心加载类派采购员：去拉货
③SpringFactoriesLoader读 spring.factories 或 AutoConfiguration.imports翻货单：列出候选
④@Conditional 过滤@ConditionalOnClass / @ConditionalOnMissingBean过安检：不合格退货
⑤配置类解析注入 Bean保留下来的类生效上架：合格品摆上货架
⑥@ConditionalOnMissingBean用户自定义优先让位：顾客自带货优先

补充：@ConditionalOnClass 看类路径（能不能装），@ConditionalOnMissingBean 看容器（要不要让位），前者看环境后者看用户。

补充：spring.factories 是 2.x 写法（所有配置类塞一个文件），3.x 改用 AutoConfiguration.imports（一行一个全限定名，更清晰）。

四、对 SpringBoot 的理解：五大特性

脚手架+起步依赖+简化配置+内置容器+依赖管理

SpringBoot 不是新框架，而是 Spring 的脚手架，解决"配置地狱"和"依赖冲突"两大痛点。

特性含义解决的痛点记忆画面
① 快速开发脚手架开箱即用项目搭建慢装修样板房：拎包入住
② 起步依赖starter 一行集成依赖版本难配套餐：一份全齐
③ 简化配置约定优于配置XML 配置地狱默认值：不填就用合理值
④ 内置容器内嵌 Tomcat部署需独立容器自带厨房：不用外借灶台
⑤ 依赖管理版本统一管理第三方版本冲突总调度：版本统一发号

补充：起步依赖（spring-boot-starter-xxx）聚合一组坐标本身不含代码，自动配置（@EnableAutoConfiguration）根据条件注入 Bean，前者管依赖后者管 Bean。

五、启动原理三阶段

初始化招工→事件发令→刷新施工

从源码视角，启动可拆成初始化、事件驱动、容器刷新三阶段。

阶段动作关键点记忆画面
① 初始化读环境变量、spring.factories、初始化器、监听器准备扩展点备料：工具人到位
② 事件驱动监听器发布事件、createApplicationContext事件触发上下文创建发令枪：监工喊开工
③ 容器刷新refresh 加载自动配置类、解析 @Import自动装配在此发生施工：图纸落地成房

补充：初始化阶段（构造 SpringApplication 时读 spring.factories 拿监听器）≠ 运行阶段（run() 中发布 ApplicationStartedEvent 等事件），前者招工后者开工后发通知。

六、高频场景题

自动装配机制+用户覆盖+启动慢定位+版本演进

"SpringBoot 自动装配是怎么实现的？"

诊断：问机制链路。答六步：开启 → 导入 → 加载 → 过滤 → 注入 → 用户优先。

"为什么我自定义的 Bean 能覆盖自动配置？"

诊断：问 @ConditionalOnMissingBean 优先级。自动配置类检测到用户已定义同名 Bean 就跳过注入。

"SpringBoot 启动慢，可能卡在哪一步？"

诊断：问启动流程定位。可能卡在 finishBeanFactoryInitialization（实例化过多 Bean）或自动配置类过多，可用延迟初始化排查。

"spring.factories 和 AutoConfiguration.imports 有什么区别？"

诊断：问版本演进。2.x 用 spring.factories，3.x 改用 AutoConfiguration.imports，一行一个类名更易维护。

七、面试回答模板

三句话讲清一题：本质→机制→实战

自动装配原理：问题本质是 SpringBoot 如何"零配置"集成第三方组件。机制是 @EnableAutoConfiguration 开启 → SpringFactoriesLoader 加载候选 → @Conditional 按需过滤 → @ConditionalOnMissingBean 保证用户优先。实战中我会用 debug=true 查看生效的自动配置类，用 @ConditionalOnMissingBean 自定义覆盖默认实现。

启动流程：问题本质是 SpringApplication.run 如何把 main 方法变成可运行 Web 应用。机制是推断类型 → 加载监听器 → 准备 Environment → 创建并刷新上下文 → 自动装配 → 启动内嵌 Tomcat → Runner 回调。实战中我会用 ApplicationRunner 做启动后初始化，用 EventListener 监听关键节点做监控。

对 SpringBoot 的理解：问题本质是 SpringBoot 解决了什么问题。机制是它通过起步依赖、自动配置、内嵌容器、约定优于配置，把 Spring 从"重型框架"变成"开箱即用脚手架"。实战中我会优先用 starter 集成，用 application.yml 覆盖默认值，需要时再自定义 Bean 覆盖自动配置。
