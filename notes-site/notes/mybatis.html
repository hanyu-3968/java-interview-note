运行四环节 + resultMap 映射 + 批量插入 + 主键回填 + 一二级缓存。

一、字段名与属性名不一致：resultMap 映射

别名改 SQL，resultMap 改映射，优先用 resultMap。

实体类属性名和表字段名对不上时，查询结果会丢值。两种解法，优先用 resultMap。

方式写法优点缺点
方式 1：SQL 别名SELECT user_name AS userName FROM t_user零配置，改 SQL 即可SQL 与映射耦合，多表复用差
方式 2：resultMap<resultMap> 标签显式映射列与属性解耦、可复用、支持多表关联需额外写映射配置

resultMap 核心写法：

<resultMap id="userMap" type="User">
  <id column="user_id" property="userId"/>
  <result column="user_name" property="userName"/>
</resultMap>
<select id="findById" resultMap="userMap">
  SELECT user_id, user_name FROM t_user WHERE user_id = #{id}
</select>

补充：resultType 和 resultMap 二选一，不能同时用。resultType 适合字段名与属性名一致（或别名后一致）的简单场景；resultMap 适合字段名不一致、多表关联、一对多/多对多复杂映射。别用 resultType=Map 凑合——丢失类型信息且字段名大小写敏感。

二、结果封装：反射创建对象并赋值

resultMap 定义映射，反射 new 对象、set 属性。

MyBatis 把 ResultSet 转成 Java 对象，靠的是 resultMap + 反射。

步骤做什么关键组件
1读取 resultMap 中列与属性的映射关系ResultSetHandler
2通过反射调用无参构造创建目标对象Class.newInstance() / Constructor
3遍历 ResultSet 列，按映射用反射给属性赋值Field.set() / setter
4处理关联对象（association/collection）递归封装嵌套 resultMap

核心机制：ResultSetHandler.handleResultSets() 根据 resultMap 的元数据，用反射创建对象、用反射给属性赋值，把数据库行 → Java 对象。这就是"为什么属性名要和列名对应"——反射按 property 名找 setter/field。

补充：反射赋值走的是 setter 方法（如果存在），不是直接 set field；没有 setter 时才走 field 反射（需 autoMapping 或 accessField 配置）。所以实体类要么提供无参构造 + setter，要么用 @Builder + 默认构造。

三、批量插入：foreach 拼接 SQL

foreach 遍历 list，逗号拼单条多行 VALUES。

单条 insert 循环太慢，用 <foreach> 一次拼多条 VALUES。

标签/属性作用记忆画面
<insert>定义插入语句装数据的箱子
parameterType="java.util.List"声明参数是 List进货清单
<foreach>遍历集合拼 SQL流水线逐件打包
collection="list"集合名（List 默认 list）取哪摞货
index="i"下标第几件
item="u"当前元素别名这件货叫 u
separator=","元素间分隔符货之间隔开
<include refid="cols"/>引用 sql 片段复用同款包装

批量插入写法：

<insert id="batchInsert" parameterType="java.util.List">
  INSERT INTO t_user (user_name, age) VALUES
  <foreach collection="list" item="u" separator=",">
    (#{u.userName}, #{u.age})
  </foreach>
</insert>

补充：批量插入有两种拼法——① VALUES (...),(...),(...) 一条 SQL 多行（推荐，一次网络往返）；② separator=";" 拼多条 INSERT 语句（需 JDBC URL 加 allowMultiQueries=true，有 SQL 注入风险，不推荐）。优先用第一种单条多行 VALUES。

四、主键回填：useGeneratedKeys

自增用 useGeneratedKeys，非自增用 selectKey。

自增主键插入后，把生成的主键塞回参数对象，供后续逻辑使用。

配置作用适用
useGeneratedKeys="true"开启自增主键回填仅自增长策略
keyProperty="id"回填到参数对象的哪个属性实体类主键字段
<selectKey> 标签自定义取主键 SQL（如序列、UUID）非自增主键

写法：

<insert id="insert" useGeneratedKeys="true" keyProperty="id">
  INSERT INTO t_user (user_name) VALUES (#{userName})
</insert>

执行后 user.getId() 即可拿到回填的主键值。

补充：useGeneratedKeys 只对自增长主键有效；Oracle 序列、UUID 等非自增主键要用 <selectKey> 标签自定义取值（如 SELECT SEQ_USER.NEXTVAL FROM DUAL）。keyProperty 是实体属性名，不是列名。

五、运行原理四环节：解析 → 代理 → 执行 → 封装

解析 Configuration → 代理 MapperProxy → 执行 Executor → 封装三 Handler。

MyBatis 从接口调用到结果返回的完整链路，分四个环节。

环节时机做什么核心组件
1. 解析启动时读取所有 XML 配置文件，把 SQL 和参数配置封装到 Configuration 全局对象XMLConfigBuilder
2. 代理运行时JDK 动态代理为 Mapper 接口生成代理对象，调用方法时代理拦截转交 MapperMethod 处理，按操作类型路由到 SqlSession 对应方法MapperProxy / MapperMethod
3. 执行运行时SqlSession 把任务交给 Executor 执行器（总调度者）Executor
4. 封装运行时Executor 协调三个核心 Handler 完成预编译、设参、结果封装StatementHandler / ParameterHandler / ResultSetHandler

三大 Handler 职责：

Handler职责记忆画面
StatementHandler预编译 SQL、创建 Statement厨师备锅
ParameterHandler给 SQL 设置参数厨师下料
ResultSetHandler把查询结果封装成 Java 对象厨师装盘上菜

完整链路：接口调用 → MapperProxy 拦截 → MapperMethod 路由 → SqlSession 对应方法 → Executor 调度 → StatementHandler 预编译 → ParameterHandler 设参 → 执行 SQL → ResultSetHandler 封装结果 → 返回。

补充：Executor 才是"总调度者"，SqlSession 只是门面（Facade）。Executor 有三种实现：SimpleExecutor（默认，每次新建 Statement）、ReuseExecutor（复用 Statement）、BatchExecutor（批处理）。缓存挂在 Executor 上，不是挂在 SqlSession 上。

六、一级缓存与二级缓存

一级 SqlSession 默认开，二级 Mapper 默认关，查询顺序二→一→库。

MyBatis 自带两级缓存提速查询。一级默认开，二级默认关。

对比维度一级缓存二级缓存
作用范围SqlSession 级别Mapper（namespace）级别
默认状态默认开启默认关闭，需手动开启
跨 SqlSession互不影响（各自独立）跨 SqlSession 共享
失效时机SqlSession 关闭/commit/rollback/执行 update执行该 namespace 的 insert/update/delete
存储位置Executor 内部 HashMap跨 SqlSession 的装饰器层
开启方式无需配置<cache/> + 实体类 Serializable

二级缓存开启：

<!-- Mapper.xml 中加一行 -->
<cache/>
<!-- 实体类需实现 Serializable -->

查询顺序：二级缓存 → 一级缓存 → 数据库。二级缓存命中直接返回；未命中查一级缓存；仍未命中查数据库，结果回填一级再回填二级。

补充：一级缓存是 SqlSession 级，不同 SqlSession 之间数据互不影响——这就是为什么 A 会话 update 后，B 会话还能查到旧数据（脏读）。二级缓存是 Mapper 级跨会话共享，但只要该 namespace 执行了任意 insert/update/delete，整个 namespace 的二级缓存全部清空（粒度粗，容易误清）。分布式环境下二级缓存不共享，需换 Redis 等分布式缓存。

七、`#{}` 与 `${}` 的区别

#{} 预编译安全传值，${} 拼接用于结构有风险。

补充高频考点：两种占位符机制完全不同，用错有 SQL 注入风险。

对比维度#{}${}
底层机制PreparedStatement 占位符 ? + 参数设置字符串直接拼接进 SQL
SQL 注入安全（预编译转义）有注入风险
参数类型自动类型处理纯字符串替换
适用场景传值（where 条件、insert 值）动态表名、列名、排序字段
引号自动加引号不加引号

补充：#{}` 是预编译占位符（?），安全但不能用于表名/列名/ORDER BY 字段（预编译不支持结构化元素）；${} 是字符串拼接，能用于动态表名/列名但有注入风险，必须先校验白名单再用。日常传值一律用 #{}，只有动态表名/排序字段才用 ${} 且要严格校验。

八、面试串联话术

映射→批量→主键→四环节→缓存一气呵成。

字段名与属性名不一致：方式 1 SQL 别名、方式 2 resultMap，优先 resultMap 解耦可复用。结果封装靠 ResultSetHandler 按 resultMap 用反射创建对象、用反射给属性赋值。

批量插入用 foreach 遍历 list，item 取元素，separator 逗号拼单条多行 VALUES（推荐）。主键回填：自增用 useGeneratedKeys + keyProperty，非自增用 selectKey。

运行四环节：解析（XMLConfigBuilder → Configuration）→ 代理（MapperProxy → MapperMethod 路由）→ 执行（Executor 总调度）→ 封装（StatementHandler 预编译、ParameterHandler 设参、ResultSetHandler 封装结果）。

缓存：一级 SqlSession 级默认开（跨会话互不影响），二级 Mapper 级默认关（跨会话共享，namespace 任意更新全清空）；查询顺序二→一→库。#{} 预编译安全传值，${} 拼接用于动态表名/列名需白名单校验。
