equals/hashCode 协同 + 反射三阶段 + 泛型擦除 + JDK 动态代理。

一、equals 方法为什么必须重写 hashCode

equals 比值，hashCode 定散列位置，二者必须协同。

维度说明
equals 默认行为Object 的 equals 默认用 == 比较对象地址，想比较值必须重写
hashCode 作用主要用于提升查询效率，确定对象在散列结构（HashMap/HashSet）中的存储位置
协同规则重写 equals 必须重写 hashCode，二者参与计算的属性字段应该相同
散列校验标准hash 结构添加元素时先比 hashCode，后判断 equals
等价关系equals 相等 → hashCode 一定相等；hashCode 相同 ≠ 对象相同（只是散列到同一桶）

补充："hashCode 相同代表对象相同"是错的。hashCode 相同只说明两个对象在散列结构中落在同一个数组桶里（哈希冲突），是否真的相等还要靠 equals 判断。反过来，equals 相等则 hashCode 必须相等——否则两个"相等"的对象散列到不同桶，HashMap 里就会存两份。

二、反射机制

运行时动态获取类信息并调用方法，三阶段流转。

反射将类的各个部分封装成对象，对于任意一个类都能知道其所有属性和方法，对于任意一个对象都能调用其任意方法和属性。

阶段发生什么关键产物
源代码阶段java 文件编译生成字节码文件Student.class（在硬盘）
类对象阶段类加载器把 class 的成员变量/构造方法/成员方法加载到内存Class 对象
运行时阶段创建对象、调用方法实例对象

反射的典型使用：Dubbo 泛化调用——把接口全路径、方法名、参数类型配置在数据库表，通过 GenericService.$invoke 动态执行，底层就是 Class.forName() 加载类 + Method.invoke() 执行方法。新增下游接口只需在配置表插一条记录，无需改代码重新发布。

补充：反射的"类对象阶段"是把类的结构信息（字段、方法、构造器）加载成 Class 对象，不是创建实例。实例是在"运行时阶段"通过 Class 对象创建的。Class 对象每个类只有一个，实例可以有多个。

三、泛型

编译时类型检查，编译后擦除为 Object。

核心作用说明
编译时类型安全编译期就能发现类型错误，避免运行时 ClassCastException
消除强制类型转换使用时无需手动转型，代码更简洁
代码复用一套代码适用于多种数据类型
泛型擦除编译时做类型检查，编译后把泛型参数擦除替换成 Object，编译器自动插入强转代码

补充：泛型是编译期机制，运行时不存在。编译后泛型参数被擦除（替换成 Object 或上界），所以 List<String> 和 List<Integer> 在运行时是同一个 Class（List）。这也是为什么不能用 instanceof List<String> 的原因——运行时拿不到泛型参数。

四、JDK 动态代理

运行时动态生成代理类，单继承所以必须接口。

原理：运行时在内存中动态构建一个代理类（实现接口），编译执行，JVM 停止代理类就消失。

步骤做什么
1. 实现接口代理类实现被代理的业务接口
2. 静态块反射方法通过静态块反射业务接口的方法，得到 Method 对象
3. 调用父类构造器调用父类 Proxy 构造器，传入 InvocationHandler 参数
4. 重写接口方法重写接口方法时调用父类 Proxy 的 h.invoke 方法

为什么动态代理必须有接口？通过父类 Proxy 的构造方法保存了创建代理对象时传入的 InvocationHandler 实例。因为 Java 是单继承的，代理类 $Proxy0 继承了 Proxy 后，只能通过实现接口的方式来扩展方法。没有接口就没有方法可以代理重写。

补充：JDK 动态代理只能代理接口（因为单继承已占用 extends Proxy），这是它和 CGLIB 的核心区别——CGLIB 通过继承目标类生成子类代理，所以能代理普通类但不能代理 final 类/方法。Spring AOP 默认：有接口用 JDK 动态代理，无接口用 CGLIB。

五、面试串联话术

对象相等→反射→泛型→代理一气呵成。

equals 默认用 == 比地址，比值要重写；hashCode 定散列位置，重写 equals 必重写 hashCode（用相同字段），否则相等对象散列到不同桶，HashMap 存两份。hashCode 相同只是哈希冲突落同桶，是否相等靠 equals。

反射三阶段：源代码（.class）→ 类对象（Class 承载结构）→ 运行时（创建实例调用方法）。Dubbo 泛化调用就是反射的典型应用，配置化动态执行接口。

泛型编译时类型检查，编译后擦除为 Object，运行时无泛型（List<String> 和 List<Integer> 运行时同 Class）。

JDK 动态代理运行时生成代理类，单继承已占 extends Proxy，只能 implements 接口扩展方法，所以必须接口；代理普通类用 CGLIB（继承生成子类）。
