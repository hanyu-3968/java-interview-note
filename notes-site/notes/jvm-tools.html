JVM 四大排障工具 + Arthas 在线诊断，覆盖微服务全链路。

一、Apollo · 分布式配置中心

长连接推送 + 本地缓存兜底，配置实时生效。

携程研发的分布式配置中心，集中化管理不同环境、不同集群的配置，修改后实时推送到应用端，适用于微服务配置管理场景。

  • 长连接接收服务端配置变更推送，定时拉取作为兜底，确保最终一致。
  • 配置缓存到本地文件系统，服务端不可用时客户端仍可读取，保证启动与运行。
  • 对外提供配置获取 API 与变更订阅机制。

二、jstat · 实时看板

实时监控 GC、类加载、JIT 编译状态。

JDK 自带轻量级命令行工具，核心作用是实时查看 JVM 内部状态，擅长监控垃圾回收与类加载。

  • GC 状态：各内存区域使用率，Young GC / Full GC 次数与耗时。
  • 类加载：当前加载、卸载的类数量。
  • JIT 编译：即时编译器编译方法数与耗时。

典型命令：jstat -gcutil 25048 5000 100（每 5 秒一次，共 100 次）。

S0     S1     E      O      M     CCS    YGC    YGCT   FGC   FGCT    GCT
0.00  67.08  32.43  80.15  93.55  87.09  691   4.923  397  10.099  15.022

读数关注点：

  1. FGC 频率过高 → 应用内存分配极快，堆几乎无空闲。
  2. O（老年代）降一点又回升 → 老年代有大量无法回收对象。
  3. M（元空间）逼近临界值 → 可能触发 Metaspace Full GC；建议调大 -XX:MaxMetaspaceSize 或排查动态类加载泄漏。

补充：jstat 各列含义——S0/S1 两个 Survivor 区占比，E Eden，O 老年代，M 元空间，CCS 压缩类空间，YGC/YGCT Young GC 次数与累计耗时，FGC/FGCT Full GC 次数与累计耗时，GCT GC 总耗时。

三、jmap · 内存快照

导出 Heap Dump，注意会触发 STW。

导出内存快照（Heap Dump），导出时会暂停应用（STW）。典型命令：jmap -dump:live,format=b,file=heap.hprof <PID>。

四、jstack · 线程堆栈

查死锁、CPU 飙高、应用卡死三大场景。

JDK 自带轻量级工具，打印指定 Java 进程的线程堆栈（Thread Dump），用于排查死锁与高 CPU 占用对应的代码行。

  • 线上 CPU 飙升：top -Hp <PID> 找到高 CPU 线程 ID（十进制）→ 转十六进制 → 在 jstack 输出中搜索定位代码行。根因多为死循环或密集计算。
  • 应用卡死 / 接口超时：连续执行 3~5 次 jstack，间隔几秒，对比输出。线程反复 BLOCKED / WAITING → 锁竞争或死锁。
  • 怀疑死锁：jstack -l <PID> 会自动检测，输出 Found one Java-level deadlock: 并圈出互等线程。

补充：线程 ID 十进制转十六进制可用 printf "%x\n" <tid>；jstack 输出中线程 nid 字段即十六进制线程 ID。

五、MAT · 堆内存分析法医

三板斧定位内存泄漏到具体代码行。

Java 堆内存分析工具，分析 .hprof 堆转储，找出内存泄漏。

定位三板斧：

  1. Leak Suspects Report 看整体印象。
  2. Histogram / Dominator Tree 定位"大对象"或"多对象"。
  3. Path to GC Roots（排除弱/软/虚引用）顺引用链找到导致无法释放的代码位置。

Path to GC Roots 展示对象到 GC Roots 的引用链；若本应回收的对象可经此路径到达 GC Roots，说明被强引用链持有，无法回收 → 内存泄漏。

六、Arthas · 在线救火队长

不重启应用，整合 jstat/jstack/jmap 交互式诊断。

Java 应用诊断利器，允许在不重启应用的情况下实时探查线上运行中的进程。

经典案例：

  1. 发现问题：线上 CPU 持续飙高。
  2. 定位线程：dashboard 发现 pool-7-thread-1 CPU 持续 90%+。
  3. 查看栈：thread <线程ID> 发现卡在 java.util.regex.Pattern 正则匹配。
  4. 监控方法：watch com.example.aop.LogAspect cutMethod '{params}' 发现 100KB 超长字符串触发正则回溯爆炸。

优势：整合 jstack/jmap/jstat 功能，提供 thread -n5、dashboard 等命令，无需记忆命令参数与线程 ID 转换；轻量敏捷，下载 arthas-boot.jar 即可运行。

七、Docker 与 K8s · 容器化与编排

Docker 打包隔离，K8s 编排运维。

Docker 软件容器平台：镜像（特殊文件系统，含程序/库/资源/配置）→ 容器（镜像运行实例，相互隔离）→ 仓库（集中存储与分发）。主要功能：构建、打包、分发、运行单个容器。

K8s 容器编排平台：自动化部署、弹性伸缩、负载均衡、服务发现、故障自愈；多主机集群。Docker 解决打包与环境隔离，K8s 解决大规模部署与运维。

八、流量入口与 Web 容器

Nginx 挡入口，Tomcat 跑业务，Netty 做内部 RPC。

  • Nginx（C 语言）：反向代理、负载均衡、限流熔断；基于 NIO 事件驱动，并发强、内存极低。
  • Apache（C 语言）：Web 服务器与反向代理，进程/线程驱动，功能丰富但高并发耗资源，多用于老系统。
  • Tomcat（Java）：标准 Servlet 容器，Spring Boot 默认内嵌。
  • Jetty（Java）：更轻量灵活，启动极快，适合嵌入式或频繁重启的开发环境。
  • Netty：高性能 NIO 网络编程工具箱，可自定义 TCP/UDP/HTTP/WebSocket 协议，微服务 RPC 调用基石。

微服务协同链路：用户浏览器 → Nginx（反向代理/限流）→ Tomcat/Jetty（运行 Spring Boot 业务）→ Netty（调用下游 Dubbo RPC）→ 数据库。

九、Janus · 统一监控平台

SkyWalking 链路 + Prometheus 指标 + ELK 日志。

基于 Java + Vue 的企业级系统：集成 SkyWalking 做链路追踪，Prometheus / InfluxDB 存指标，ELK Stack（Elasticsearch + Logstash + Kibana）做日志采集、检索与分析。

十、排障思路串联

jstat 宏观报警 → jstack 微观现场 → jmap 根本证据。

先用 jstat 发现 O 区占满、GC 频繁（宏观报警）→ 再用 jstack 看是否大量线程 BLOCKED 导致任务堆积（微观现场）→ 最后用 jmap 导出 Dump 查内存泄漏（根本证据）。
